# “养护手册”卡片库与服务 SOP 接入计划

更新日期：2026-07-20

## 1. 项目目标

在管理后台新增“养护手册”页面，从有赞店铺笔记中同步并展示标题包含“养护注意事项”的已发布笔记。系统不把笔记正文写入 RAG，也不让 AI 阅读或复述正文；AI 和服务 SOP 只使用手册名称、适用品种、封面和跳转链接，向用户发送对应的微信链接卡片。

核心业务规则：

1. 用户拥有“抖音已购”或“微信已购”标签，进入服务 SOP。
2. 该用户的开场白组合消息已经实际发送成功，而不是仅进入发送队列。
3. 系统已经确认用户购买的兰花品种时，查找对应的养护手册并发送链接卡片。
4. 系统不知道用户购买的兰花品种时，先发送：

   > 亲想问一下您是购买了我们家的哪一款产品？方便说一下兰花名称吗？

5. 用户回答后提取兰花名称，再次匹配养护手册并发送卡片。

## 2. 已确认的外部能力

### 2.1 有赞店铺笔记

- 接口：`youzan.showcase.shopnote.list`
- 版本：`1.0.0`
- 真实店铺调用已成功，店铺当前约有 482 条笔记。
- 可取得的卡片相关字段包括：`note_id`、`note_alias`、`title`、`cover_photos`、`note_url`、`note_status`、`publish_time` 等。
- 已存在类似 `【建兰玉白丹红】养护注意事项` 的真实笔记，返回的 `note_url` 可作为微信链接卡片跳转地址。

同步阶段必须先确认该接口的真实分页参数。此前尝试普通的 `page/page_size` 和 `page_no/page_size` 均仍返回第一页，因此不能以“第一页 20 条”冒充全量同步。

### 2.2 易云微信链接卡片

- 使用官方“发送链接”能力：`POST /sendUrl`。
- 必要字段：`wId`、`wcId`、`title`、`url`、`description`、`thumbUrl`。
- 成功判定：响应 `code == "1000"`。
- 项目已有链接卡片发送、失败重试、限速、依赖消息和发送状态回写能力，养护手册复用该链路。

第一期发送有赞返回的 H5 `note_url` 链接卡片。只有在取得并验证店铺笔记对应的小程序 `pagePath` 后，才切换为小程序卡片，不能根据 H5 链接猜测小程序路径。

## 3. 数据范围与同步规则

### 3.1 收录条件

一条店铺笔记必须同时满足以下条件才进入卡片库：

- `title` 包含完整文字“养护注意事项”；
- 笔记处于已发布、可访问状态；
- `note_id`、标题和跳转链接有效。

不满足条件的笔记不在“养护手册”页面展示，也不参与 AI 或 SOP 匹配。

### 3.2 同步行为

- 按 `note_id` 幂等更新，重复同步不产生重复卡片。
- 新增符合条件的笔记时创建卡片。
- 有赞侧改名、换封面或换链接时更新外部字段。
- 笔记下架、删除、不可访问或标题不再包含“养护注意事项”时，将本地卡片标记为不可用，不物理删除。
- 同步不得覆盖管理员维护的品种别名、产品关联、排序、启用状态和备注。
- 保存每次同步的开始时间、结束时间、扫描数量、符合数量、新增/更新/停用数量和失败原因。
- 支持后台手动同步；稳定后再增加定时同步。

### 3.3 不进入 AI 的内容

- 不调用笔记正文详情接口。
- 不把正文、摘要或页面抓取内容写入 Qdrant/RAG。
- 不向模型提供笔记正文或有赞接口原始响应。
- 模型只看到经过筛选的卡片元数据：手册名称、匹配品种、链接、封面和卡片 ID。

## 4. 数据库设计

新增 `care_manual_cards`：

| 字段 | 用途 |
| --- | --- |
| `id` | 本地主键 |
| `youzan_note_id` | 有赞笔记 ID，唯一 |
| `note_alias` | 有赞笔记别名 |
| `title` | 手册标题 |
| `orchid_name` | 从标题或人工配置得到的标准兰花名称 |
| `aliases_json` | 兰花别名、简称、商品标题关键词 |
| `note_url` | H5 跳转链接 |
| `cover_url` | 卡片封面 |
| `card_description` | 固定或人工维护的卡片描述，不取正文 |
| `youzan_status` | 有赞发布状态 |
| `enabled` | 管理员是否允许发送 |
| `sort_order` | 同一品种多卡片时的优先级 |
| `match_keywords_json` | 人工维护的匹配关键词 |
| `published_at` | 有赞发布时间 |
| `last_synced_at` | 最近同步时间 |
| `created_at/updated_at` | 本地时间戳 |

新增 `care_manual_product_links`，把养护手册与本地产品/有赞商品建立明确关联：

- `care_manual_card_id`
- `catalog_product_id` 或 `youzan_item_id`
- `product_name_snapshot`
- `created_at/updated_at`

新增 `care_manual_delivery_logs` 记录整个闭环：

- 用户、会话、服务 SOP enrollment、卡片 ID；
- 品种来源和匹配方式；
- 触发原因；
- 易云发送消息 ID、发送状态和失败原因；
- 创建时间、发送时间。

为 `(service_sop_enrollment_id, care_manual_card_id)` 建唯一约束，避免同一次服务 SOP 进入过程重复发送同一手册。

数据库继续使用云服务器上的持久化目录 `/home/ubuntu/intelligent-customer-service/runtime-data`，随 API 容器挂载，不把数据库文件打进镜像。上线前执行备份和迁移验证。

## 5. “养护手册”后台页面

导航位置：与“产品信息”同级，页面名称为“养护手册”。

页面包含：

- 顶部统计：有效手册、停用手册、未绑定品种、最近同步状态；
- “立即同步”按钮和最近一次同步结果；
- 按手册名、兰花品种、关键词搜索；
- 按启用状态、匹配状态筛选；
- 卡片列表展示封面、标题、标准品种、别名、产品关联、状态、发布时间和链接；
- 编辑标准品种、别名、产品关联、卡片描述、排序和启用状态；
- 点击预览真实跳转链接；
- 单条测试匹配功能，只展示匹配结果，不向真实微信联系人发送。

列表接口必须在服务端再次强制校验标题包含“养护注意事项”，不能只依赖前端过滤。

## 6. 兰花品种识别与匹配

### 6.1 “已知购买品种”的可信来源

按以下优先级取值：

1. 已验证订单的商品明细与 `care_manual_product_links` 精确关联；
2. 用户在当前追问流程中明确回复的兰花名称；
3. 当前或近期用户消息中明确出现、且能唯一匹配的兰花名称；
4. 用户画像中已保存、来源明确的已购产品事实。

“用户喜欢的兰花品类”标签只能表示偏好，不能当成已经购买的具体品种。AI 推测、相似但不唯一的商品名、客服示例文本也不能作为发送依据。

### 6.2 标准化规则

- 从类似 `【建兰玉白丹红】养护注意事项` 的标题中去除括号和固定后缀，得到标准品种名。
- 统一全角/半角、空格、常见标点和大小写。
- 商品标题中的规格、盆数、赠品、促销词由产品关联或人工别名处理。
- 优先级为：商品精确关联 > 标准品种精确匹配 > 人工别名精确匹配 > 人工关键词匹配。
- 模糊匹配只能生成候选，不能直接自动发送。

### 6.3 匹配结果处理

- 唯一匹配：发送该手册卡片。
- 同一品种存在多条有效手册：按人工排序选第一条；自动流程默认只发一张，避免刷屏。
- 多个不同品种均由已验证订单确认：按去重后的品种逐张发送，默认单次最多 3 张，并受现有限速和消息依赖链控制。
- 多个候选但无法唯一确认：追问用户选择具体名称，不自动发送。
- 已知品种但没有手册：不发送近似卡片，写入“待补充映射”列表，交给管理员补齐。

## 7. 服务 SOP 触发状态机

```text
购买标签成立
  -> 创建/确认服务 SOP enrollment
  -> 等待开场白全部发送成功
  -> 获取已购兰花品种
     -> 已知且唯一匹配：排队发送养护手册链接卡片
     -> 未知：发送固定追问，进入 awaiting_orchid_name
        -> 用户回复可唯一匹配：保存品种事实并发送卡片
        -> 用户回复存在多个候选：发送名称澄清问题
        -> 用户回复仍无法匹配：保留等待状态或转人工，不猜测发送
```

关键实现要求：

- “开场白已发送”以组合消息中最后一条 outbound 的状态为 `sent` 为准。
- 养护手册消息依赖开场白最后一条消息，前序失败时不得越过发送。
- 未知品种追问也在开场白成功后发送，并写入 `care_manual_pending = awaiting_orchid_name`。
- 下一条用户回复即使被普通意图识别为闲聊，也要优先恢复该 pending 流程。
- 成功识别或人工终止后清除 pending 状态。
- 同一 enrollment 的固定追问只主动发送一次；失败可以按现有发送队列规则重试，成功后不重复追问。
- 用户转人工、删除好友、购买标签撤销或服务 SOP enrollment 退出时，取消尚未发送的养护手册任务。

## 8. AI Tool Call 设计

为 AI 开放受控工具，不开放数据库、SQL 或原始有赞接口：

### 8.1 `search_care_manual_cards`

输入：

```json
{
  "query": "玉白丹红",
  "product_name": "建兰玉白丹红",
  "youzan_item_id": "可选",
  "limit": 3
}
```

输出仅包含：

```json
{
  "matches": [
    {
      "card_id": 1,
      "title": "【建兰玉白丹红】养护注意事项",
      "orchid_name": "建兰玉白丹红",
      "note_url": "https://...",
      "cover_url": "https://...",
      "match_type": "exact_product"
    }
  ]
}
```

### 8.2 `send_care_manual_card`

输入只接受内部 `card_id` 和当前会话标识。服务端重新检查：

- 当前用户是否处于有效服务 SOP；
- 开场白是否已成功发送；
- 卡片是否有效、启用且标题仍符合过滤规则；
- 品种是否有可信来源并与卡片匹配；
- 是否已经发送过；
- 当前微信实例和用户标识是否有效。

检查通过后，服务端自行组装 `/sendUrl` 参数并进入统一发送队列。AI 不得传入任意 URL、封面或任意收件人，避免把工具变成通用外发接口。

自动服务 SOP 触发优先使用确定性服务完成查找和发送；AI Tool Call 用于对话中的补充查询和明确用户请求，二者共用同一匹配、权限、幂等和审计逻辑。

## 9. 接口与服务拆分

后端计划新增：

- 有赞手册同步服务：分页拉取、过滤、标准化、幂等更新；
- 养护手册管理 API：列表、详情、编辑、启停、产品关联、手动同步；
- 养护手册匹配服务：统一品种标准化和候选排序；
- SOP 触发服务：监听 enrollment、开场白发送完成和 pending 用户回复；
- AI 工具服务：搜索与受控发送；
- 发送审计服务：记录匹配来源、发送状态和失败原因。

前端计划新增：

- 路由和导航入口；
- 卡片列表、筛选、编辑、预览和同步结果；
- 未匹配品种提示与产品关联编辑；
- 只匹配不发送的测试面板。

## 10. 开发顺序

### 阶段一：同步与卡片库

1. 确认有赞接口真实分页方式，并在云服务器出口 IP 下完成全量分页实测。
2. 增加数据库表和迁移。
3. 完成同步、过滤、幂等更新和停用逻辑。
4. 完成“养护手册”后台页面和管理接口。

### 阶段二：匹配与服务 SOP

1. 完成标题标准化、别名和产品关联匹配。
2. 增加开场白发送完成事件和养护手册状态机。
3. 接入未知品种固定追问及 pending 恢复。
4. 接入链接卡片队列、幂等约束和发送日志。

### 阶段三：AI 工具

1. 注册搜索与发送工具。
2. 将工具加入真实 AI 可用工具清单和系统提示边界。
3. 完成权限校验、参数校验、结果脱敏和审计。
4. 在测试联系人上验证真实 Tool Call 到微信卡片的完整链路。

### 阶段四：上线

1. 本地完成迁移和针对性测试。
2. 检查 diff、敏感信息和数据库文件，提交并推送 `main`。
3. 云服务器只通过 `git pull` 拉取已提交代码，执行数据库备份、迁移和容器部署。
4. 运行真实有赞同步，核对筛选总数和代表性卡片。
5. 先保持发送功能为测试/灰度状态，经指定微信测试联系人验收后再打开自动发送。

## 11. 测试与验收标准

### 同步

- 能遍历真实接口全部分页，而不是只取第一页 20 条。
- 页面上每一条标题都包含“养护注意事项”，且仅展示已发布、可用笔记。
- 重复同步不重复建卡；改名、下架、删除和重新发布能正确更新状态。
- 管理员维护的别名、关联、排序和启用状态不会被同步覆盖。

### 匹配

- 已验证商品可精确找到正确手册。
- 标准名、人工别名和商品关联的优先级符合设计。
- 多候选或低置信度时不误发。
- 已知但未配置的品种进入“待补充映射”，不发送相近手册。

### SOP

- 没有购买标签时不触发。
- 已进入服务 SOP、但开场白尚未成功时不触发。
- 开场白成功且品种已知时，只发送对应卡片。
- 品种未知时发送指定追问；用户下一条只回复品种名也能恢复流程并发送。
- 同一 enrollment、同一卡片只发送一次。
- 退出服务 SOP、删除好友或转人工后，待发送任务会取消。

### AI 与安全

- AI 只能检索卡片元数据，无法取得笔记正文。
- AI 不能指定任意收件人或任意链接发送。
- 所有查询、匹配、追问和发送都有审计记录。
- 易云失败、限速、重试和最终状态能够回写，失败不会被记录为成功。

### 真实环境验收

- 从云服务器出口 IP `150.158.52.233` 完成有赞全量同步。
- 使用指定测试联系人完成一次“已知品种直接发送”链路。
- 使用指定测试联系人完成一次“未知品种追问—回复品种—发送卡片”链路。
- 未经明确确认，不向真实客户批量开启自动发送。

## 12. 本期不做

- 不抓取、切片或向量化店铺笔记正文。
- 不让 AI 根据笔记内容生成养护回答。
- 不根据偏好标签猜测已购品种。
- 不在没有真实 `pagePath` 的情况下伪造小程序卡片。
- 不允许 AI 绕过服务 SOP、开场白、品种匹配和幂等校验直接外发。
