# 代码与架构梳理重构

## 任务目标

全面梳理项目代码与架构，在保留现有业务行为和部署方式的前提下，删除可确认的冗余、合并重复实现、改善模块职责和依赖关系。只实施有代码证据支持的优化，不引入推测性功能或新的框架。

## 实施计划

1. 阅读项目说明、目录、依赖、应用入口及关键业务模块，建立当前架构与调用链概览。
2. 检查重复实现、无效引用、职责混杂和依赖问题，按风险确定重构边界。
3. 分批实施最小必要修改，记录每批改动的依据及行为约束。
4. 根据实际影响运行必要检查，审查最终差异与敏感信息。
5. 验证通过且远端未分叉时，按项目约定提交并推送 GitLab main。

## 完成标准

- 核心业务入口、模块职责及主要依赖得到梳理。
- 删除项具有引用或调用证据；公共行为、接口与数据兼容性得到保留。
- 修改范围对应已确认的问题，必要检查通过，最终差异经过审查。
- 如存在不能安全实施的结构调整或验证限制，明确记录。

## 完成结果

- 初始工作区干净，当前分支为 main；已阅读项目根目录规则。
- 完成源码规模与 Python AST 扫描：后端 210 个 Python 文件、42,081 行；前端 45 个源码文件、8,880 行。结合路由、装配、关键服务、前端入口与运维/评测引用梳理模块边界。
- 确认实施范围：拆分 Agent 执行上下文与回复策略；提取商品持久化访问，解除 catalog 对有赞同步私有会话函数的依赖；合并两套商品导入器的公共结构与读取逻辑并关闭工作簿；调整前端公共时间工具归属并删除确认未使用的代码。
- 数据库表结构、供应商请求协议、销售策略、部署配置保持现行契约。运维脚本或评测仍有引用的模块不因生产入口未直接使用而删除。
