# SOP 节点转人工配置

## 任务目标

在现有转人工设置中增加按 SOP 节点转人工的配置能力。首单 SOP 使用破冰、挖需求、找痛点、推品、塑品、试成交和逼单七个运营节点；服务 SOP 使用问题处理与服务挖需、会员权益交付、服务收口与偏好采集、复购需求挖掘和长期关系维护五个节点。节点默认由 AI 回复，运营可在转人工页面独立开启人工接管。

## 实施计划

1. 建立前后端共用语义下的 SOP 节点目录，并在转人工设置中持久化每个节点的开关。
2. 扩展管理端查询和保存接口，返回稳定节点 ID、名称、说明和开关状态。
3. 让 Agent 每轮输出当前 SOP 节点，在执行业务工具或客户回复前检查节点开关；命中时只创建人工接管。
4. 在转人工页面按首单 SOP 和服务 SOP 分组展示节点开关，保留现有紧急总开关、通知人和通知文案。
5. 执行最小后端测试和管理端类型检查，审查最终差异。

## 完成结果

- 转人工设置新增首单 SOP 7 个节点和服务 SOP 5 个节点的独立开关，默认全部由 AI 回复。
- 后端设置接口返回节点目录和开关映射，并兼容原有未携带节点配置的更新请求。
- Agent 决策契约新增 `sop_node`，运行时在业务工具和客户回复前检查开关；命中时只创建人工接管并记录 SOP 范围和节点。
- 客户有系统核验的“抖音已购”或“微信已购”标签时进入服务 SOP，其他客户进入首单 SOP；显式传入的 `sop_scope` 保持优先。
- 新好友破冰开关开启时，在发送系统开场消息前直接转人工。
