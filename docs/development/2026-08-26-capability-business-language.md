# 能力说明业务化重构

## 任务目标

将能力工作台从研发调试视角改为业务人员可理解的能力说明：每项能力默认说明具体动作、数据来源、AI 是否可以主动调用、是否会触达客户、是否通知工作人员、业务权限、执行结果和风险等级；技术标识、执行器、幂等、错误码和 JSON 协议收进默认折叠的研发信息。

本任务只调整能力元数据和管理端展示，不修改现有能力执行器、Agent 调用逻辑或生产会话行为。

## 实施计划

1. 扩展 `CapabilityManifest`，增加统一业务说明结构和校验。
2. 为当前 16 项能力逐一补齐业务动作、来源、AI 执行方式、客户触达、工作人员通知、权限、结果和风险说明。
3. 修改管理端类型，保持前后端协议一致。
4. 重构能力卡片，移除技术标识，突出业务动作和 AI/客户影响标签。
5. 重构能力详情，默认展示业务说明，把研发字段和 JSON 协议放入折叠区。
6. 同步编排协议文档，并进行结构、类型、构建和浏览器视觉验证。
7. 审查最终差异，提交并推送 GitLab `origin/main`。

## 完成结果

- 扩展能力协议，新增统一 `business` 结构，覆盖具体动作、数据来源、AI 执行方式、客户触达、工作人员通知、业务权限、执行结果和风险说明。
- 为现有 16 项能力逐一补齐业务元数据，查询、写入、客户发送、工作人员通知和转人工的差异均已明确。
- 能力卡片移除技术标识，改为展示业务动作、AI 使用方式、客户影响和工作人员通知。
- 能力详情默认按业务视角展示具体动作、数据来源、AI 如何使用、是否触达客户、使用权限、执行结果和风险等级。
- 前置条件和使用边界分别以“什么时候可以使用”和“使用规则”展示，使用位置中的技术值已翻译为业务语言。
- 能力标识、执行器、超时、重试、幂等、技术权限、错误码和输入输出协议移入默认折叠的“研发信息”。
- 同步编排协议文档，明确 AI 是否能调用和是否会联系客户是两个独立维度。
- 未修改任何能力执行器、Agent 调用逻辑或生产会话行为。

## 验证情况

- `CapabilityCatalog` 成功校验全部 16 项能力的业务元数据。
- 能力工作台聚合服务确认每项能力均返回业务说明。
- `pnpm ts:check` 通过。
- `pnpm build:prod` 通过。
- 浏览器实际验证“查询养护手册”详情：业务信息默认可见，技术信息默认折叠且可以展开，能力卡片不再显示技术标识。
- 浏览器控制台无错误或警告。
