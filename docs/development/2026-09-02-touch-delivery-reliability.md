# 定时触达与非文本消息可靠性改造

## 任务目标

解决定时触达媒体未送达且不补发、发送状态误判、消息后台进入不及时，以及文件重复、微信系统事件和媒体无法预览的问题。

## 实施计划

1. 修正消息建模与工作台展示：分离文案和媒体记录，统一可访问媒体地址，合并文件双回调并忽略系统事件。
2. 建立可靠送达状态：区分接口受理与回调确认，增加独立媒体重试、超时恢复和补发能力。
3. 提高及时性：缩短定时任务扫描和工作台兜底刷新间隔，保留计划、入队、受理和确认时间。
4. 补齐运营闭环：提供触达状态统计、失败明细、手动补发和历史数据治理。

## 完成标准

- 定时触达到点后 10 秒内可在消息后台看到排队记录。
- 文案和图片或视频分别展示状态，媒体失败不遮挡文案。
- 图片、视频和文件通过 HTTPS 或同源地址正常预览或下载。
- 接口返回成功只标记为已受理，自身消息回调后才标记为已确认。
- 失败媒体能够独立重试，超时任务不会永久停留在处理中。
- 后台可查询触达各状态数量、失败原因并执行受控补发。

## 完成结果

- 阶段一完成：定时触达文案与媒体使用独立工作台消息，系统触达会更新会话摘要。
- 阶段一完成：视频元数据提取实际媒体和封面地址，HTTP 定时素材通过同源鉴权代理访问。
- 阶段一完成：同一文件的 60008/60009 双回调按文件名和大小合并，无地址的文件仍显示文件名。
- 阶段二完成：亿云接口成功改为 `accepted`，自身消息回调按 provider message ID 确认后改为 `confirmed`。
- 阶段二完成：受理后 120 秒未确认以及发送硬错误都会进入 1、5、15 分钟的持久补偿，最多四次后明确失败。
- 阶段二完成：文案和媒体独立确认与补偿，历史 `sent` 状态保持兼容；缺少亿云配置不再误报成功。
- 其余阶段实施中。
