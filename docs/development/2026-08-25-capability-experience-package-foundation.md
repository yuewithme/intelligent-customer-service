# 能力插件与经验包协议基座

## 任务目标

为智能客服后续改造成“数据基座 + 可插拔能力 + 经验包 + 可视化编排平台”建立第一阶段的稳定协议，不修改当前生产运行链路。

本阶段需要完成：

- 定义功能能力插件需要封装的元数据、输入输出、执行、权限、策略、可视化和版本信息。
- 定义经验包、步骤、条件、连线、结果和能力依赖的结构。
- 将现有兰花新客首单 SOP 表达为一份完整、可校验的经验包样板。
- 核对当前后端真实能力如何映射为隐藏能力、可配置能力和可拖拽动作。

## 实施计划

1. 结合现有 `agent_tools.py`、Agent 运行链路和兰花销售 SOP，确定协议边界。
2. 编写能力插件协议，明确运行语义与管理端展示分级。
3. 编写经验包协议，明确设计态、发布态和运行态的职责。
4. 编写兰花新客首单成交经验包样板，并绑定现有真实能力。
5. 对样板进行静态校验，确认引用、步骤连线、结果出口和能力依赖完整。
6. 检查最终差异；验证通过后提交并推送 Gitea `main`。

## 完成结果

- 新增独立 `orchestration` 领域契约，使用 Pydantic 定义能力清单、条件、步骤、转移、结果和经验包图结构。
- 建立当前 Agent 的能力目录，共覆盖 16 个真实后端执行器，并标记隐藏、可配置和可拖拽三种管理端展示级别。
- 将兰花新客首单 SOP 落成 `orchid.first_order` v1 样板：包含需求诊断、方案推荐、购买信号、发卡、成交推进、等待和转人工等 8 个步骤，16 条转移和 5 个结果。
- 增加协议说明，明确能力、经验包、业务数据、运行实例和可视化布局的边界，以及下一阶段的数据表映射。
- 本阶段没有接入数据库、管理端或生产 Agent，不改变当前线上运行行为。

## 验证情况

- 使用 `CapabilityCatalog.model_validate_json` 校验能力目录。
- 使用 `ExperiencePackageDefinition.model_validate_json` 校验首单经验包，并通过步骤引用、能力依赖、连线出口、结果引用、默认分支和可达性检查。
- 通过 AST 对照确认能力目录覆盖 `execute_agent_tool` 中全部 16 个真实执行器。
- 确认首单经验包的 13 项能力依赖全部存在于能力目录。
- `python -m compileall -q app/domains/orchestration` 通过。
- `git diff --check` 通过。
- 未运行完整测试套件；本阶段只新增未接入运行链路的契约和静态样板，针对性结构校验已覆盖本次风险。
