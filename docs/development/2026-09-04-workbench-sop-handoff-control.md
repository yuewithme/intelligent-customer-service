# 能力工作台 SOP 节点转人工控制

## 任务目标

将首单 SOP 和服务 SOP 的节点转人工配置全部收口到能力工作台。每一个可选业务节点都在详情区提供“AI 回复 / 转人工”开关，并沿用现有转人工设置的存储、通知人、通知文案和运行时拦截逻辑。转人工设置页删除 SOP 节点配置区，不再作为节点开关入口。

## 实施计划

1. 核对能力工作台的经验包、流程节点和详情面板数据结构，建立与现有转人工节点 ID 的稳定关联。
2. 让能力工作台返回首单 SOP、服务 SOP 及各节点开关状态，并提供保存能力。
3. 在工作台节点详情区增加转人工开关，在流程图节点上展示当前处理状态。
4. 从转人工设置页删除两个 SOP 的节点开关区，保留紧急总开关、通知人和通知文案。
5. 使用最小后端用例和管理端类型检查验证数据同步、保存和页面绑定。

## 完成结果

- 能力工作台的流程区现在直接展示首单 SOP 和服务 SOP，共 12 个业务节点，节点 ID 与线上 Agent 的 `sop_node` 一致。
- 每个流程节点在图上显示“AI 回复 / 转人工”状态，选中节点后可在右侧详情区直接切换。
- 工作台新增节点开关更新接口，原子更新现有 `sop_node_handoff_json` 配置，不改动紧急总开关、通知人或通知文案。
- 转人工设置页已删除首单 SOP 和服务 SOP 节点配置区，节点转人工只能在能力工作台管理。
- 现有 Agent 节点命中和人工接管逻辑保持不变，工作台修改后立即使用同一份持久化配置。
