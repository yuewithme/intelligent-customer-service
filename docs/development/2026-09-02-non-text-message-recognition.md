# 未识别消息识别与转人工优化

## 任务目标

将微信非文本消息从“按消息类型直接转人工”升级为“先分类、再理解内容、最后按真实业务诉求决定是否转人工”。任务分四个阶段独立实施、验证、提交并推送：

1. 统一识别系统事件、表情、卡片、小程序、文件等消息，过滤平台噪声。
2. 修复 `unsupported_message_type` 导致的错误待人工状态，并提供历史安全清理能力。
3. 下载并转写客户语音，将转写结果交给销售 Agent。
4. 对客户视频进行关键帧和音频理解，补充消息识别监控统计。

## 实施计划

### 阶段一：统一非文本消息分类

- 建立标准化的入站消息分类结果。
- 优先使用 `messageType`，对 `60999` 继续解析 `msgType`、XML 根节点、`sysmsg type` 和 `appmsg type`。
- 系统事件不创建人工工单；加好友事件进入开场流程；表情作为客户反馈；卡片、小程序等提取结构化文本后进入 Agent。
- 增加针对真实历史载荷类型的最小测试。

### 阶段二：会话状态修复

- 当后续消息成功进入 AI 流程时，仅清除由 `unsupported_message_type` 产生且未被人工接管的遗留状态。
- 保留人工已接管、人工分配和其他真实人工原因。
- 提供可审计、幂等的历史修复入口或启动修复逻辑。

### 阶段三：语音转写

- 复用现有 E 云语音下载任务。
- 将下载后的音频交给已配置模型能力转写，保存转写文本和状态。
- 转写成功后进入 Agent；失败时自然补问，不因语音格式直接转人工。

### 阶段四：视频理解与监控

- 复用现有视频下载任务，限制大小、时长和关键帧数量。
- 组合关键帧理解与音轨转写生成结构化摘要，再进入 Agent。
- 记录原始类型、标准类别、处理结果、失败原因和最终转人工原因。

## 完成结果

- 阶段一已完成：新增统一 E 云入站分类器，识别文本、图片、视频、语音、名片、表情、链接、文件、小程序、聊天记录、位置、收付款和系统事件。
- `60999` 会继续解析新好友提示、`sysmsg`、`appmsg type`、表情和图片 XML；系统事件直接过滤，表情只记录为客户反馈，卡片类消息提取标题、描述和链接后进入 Agent，真正未知类型只记录观察信息而不再直接转人工。
- 语音和视频已从“未知消息”改为明确媒体等待态，分别由后续阶段补齐内容处理。
- 阶段二已完成：`unsupported_message_type` 被纳入仅限“未被领取、未人工接管”的自动恢复范围；任何新识别消息进入回调时会先恢复遗留锁定。
- 应用启动时会幂等清理超过 24 小时、无接管人的历史 `unsupported_message_type` 会话，同时清除对应画像锁定；人工强制转接及其他真实人工原因保持不变。
- 阶段三已完成：新增基于百炼 OpenAI 兼容接口的语音转写服务，复用现有 DashScope/视觉密钥与地址，默认使用 `qwen3-asr-flash`，通过 Base64 Data URL 发送本地 WAV。
- 语音下载成功后保存转写文本、语言、情绪和时长，并将转写后的客户话语重新投递给 Agent；转写失败会保存可观察错误并投递自然补问指令，不转人工。
