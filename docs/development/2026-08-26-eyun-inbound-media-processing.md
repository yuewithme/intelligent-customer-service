# Eyun 入站语音视频可靠处理

## 任务目标

修复 Eyun 私聊视频和语音只能显示占位文字、无法可靠播放的问题。新媒体消息在回调后立即进入持久化后台任务：视频通过 Eyun 异步接口下载并本地持久化，语音通过 `getMsgVoice` 下载并转换为浏览器可播放格式；管理后台展示处理状态、失败原因并允许重试。

本任务暂不加入语音转写、视频关键帧理解或 AI 自动回复，只保证人工工作台能够可靠看到并播放新收到的语音和视频。

## 实施计划

1. 增加持久化 Eyun 入站媒体任务及启动恢复机制，以消息 ID 幂等创建任务。
2. 回调入库时完整保存语音、视频下载参数并立即排队，保持回调快速返回。
3. 视频使用 `asynGetMsgVideo` 与 `getMsgVideoRes` 下载并持久化；语音使用 `getMsgVoice` 下载并转换为浏览器可播放格式。
4. 管理后台展示处理状态、错误信息和手动重试入口，不再依赖打开会话才发起解析。
5. 使用官方形状的回调样例补充针对性测试，验证幂等、恢复、成功、失败和界面行为。
6. 审查最终差异，只提交本任务文件并推送 GitLab `origin/main`。

## 完成结果

- 新增持久化 `eyun_inbound_media_jobs` 任务表，语音和视频按会话消息幂等排队，处理中断超过阈值后自动恢复。
- Eyun `60003`、`60004` 回调在消息入库后立即创建媒体任务，不再等待管理员打开会话。
- 视频任务继续使用官方 `asynGetMsgVideo`、`getMsgVideoRes`，成功后立即下载到持久化 `/app/data/media` 目录。
- 语音任务兼容回调数据字段和 `voicemsg` XML 属性，通过 `getMsgVoice` 下载 Silk，并使用 `pilk` 转换为浏览器可播放的 WAV 文件。
- 视频和语音下载均校验响应类型、空文件和大小上限，临时文件在成功或失败后清理。
- 媒体任务最多自动尝试三次，保留提供方错误；管理后台展示处理中、失败原因和重新解析入口。
- 旧的失败媒体可以手动重新排队；旧的待处理消息没有任务标识时也会显示重新解析入口。
- 管理后台不再因打开会话或播放器报错自动调用提供方接口，媒体状态通过后台 Worker 和会话事件更新。
- 本任务未加入语音转写、视频画面理解或 AI 自动回复。
