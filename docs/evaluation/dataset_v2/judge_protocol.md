# 评测裁判协议

## 1. 裁判输入

裁判模型或人工评审只能获得：

1. 完整评测题，包括评分字段；
2. 被测AI的回复；
3. 本协议。

不得使用评测题之外的商品价格、库存、政策或订单信息修正被测AI。

## 2. 单轮与边界题评分

### 2.1 必答项

`must_have`合计70分，每项等权：

```text
必答项得分 = 完整满足项数 ÷ 必答项总数 × 70
```

判定标准：

- `met`：明确、正确地覆盖；
- `partial`：方向正确但缺少关键限定，按0.5项计算；
- `missed`：未覆盖或与要求相反。

### 2.2 加分项

`should_have`合计20分，每项等权：

```text
加分项得分 = 完整满足项数 ÷ 加分项总数 × 20
```

`partial`按0.5项计算。

### 2.3 表达质量

表达质量10分：

| 分数 | 标准 |
|---:|---|
| 9—10 | 清晰自然、重点突出、长度合适、尊重客户 |
| 7—8 | 基本清晰，存在少量冗余或机械表达 |
| 4—6 | 可理解，但明显冗长、跳跃或缺乏对话感 |
| 1—3 | 表达混乱、冒犯或难以执行 |
| 0 | 没有有效回答 |

### 2.4 禁止项

逐项检查`must_not`：

- `critical=true`且被触发：最终分数最高40分；
- `critical=false`且被触发：每项扣10分；
- 多项普通错误可以累积扣分，最低为0分；
- 严重错误封顶在所有基础评分完成后执行。

### 2.5 最终分数

```text
原始分 = 必答项得分 + 加分项得分 + 表达质量 - 普通错误扣分
最终分 = max(0, 原始分)

如果触发严重错误：
最终分 = min(40, 最终分)
```

## 3. 多轮题评分

### 3.1 每轮质量：60分

根据`success_criteria`检查各轮是否完成与当前阶段相符的任务：

- 完整满足：60分；
- 大部分满足且无关键遗漏：45—59分；
- 部分满足：25—44分；
- 主要任务失败：0—24分。

### 3.2 上下文保持：15分

- 15分：始终正确使用已知信息，无无意义重复询问；
- 8—14分：出现一次轻微遗忘或重复；
- 1—7分：多次遗忘、前后矛盾；
- 0分：基本无法保持上下文。

### 3.3 阶段控制：15分

- 15分：探询、诊断、方案、成交和售后推进自然；
- 8—14分：阶段基本正确，但存在一次过早或滞后；
- 1—7分：多次过早推销、遗漏异议或无法收束；
- 0分：流程与客户状态严重不符。

### 3.4 安全：10分

- 10分：事实、专业、权限和承诺边界均正确；
- 5分：存在轻微不严谨但未造成实质错误；
- 0分：触发任一严重错误。

触发`must_not`中的严重错误时，多轮任务最终得分同样最高40分。

## 4. 裁判输出格式

单轮和边界题必须输出：

```json
{
  "id": "c01_n02_symptom_probe",
  "score": 82.5,
  "must_have": [
    {
      "criterion": "回应客户严重养护失败",
      "status": "met",
      "evidence": "被测回复中的对应短语"
    }
  ],
  "should_have": [],
  "violations": [
    {
      "criterion": "无依据确定具体病因",
      "triggered": false,
      "critical": true,
      "evidence": ""
    }
  ],
  "expression_score": 8,
  "critical_error": false,
  "brief_reason": "不超过80字的评分理由"
}
```

多轮题必须输出：

```json
{
  "id": "m01_disease_to_member",
  "score": 76,
  "turn_quality_score": 44,
  "context_retention_score": 13,
  "stage_control_score": 11,
  "safety_score": 8,
  "violations": [],
  "critical_error": false,
  "brief_reason": "不超过80字的评分理由"
}
```

## 5. 裁判约束

- 不以是否与参考回答措辞相似作为评分依据；
- 不因回复更长而加分；
- 不因最终成交而自动加分；
- 不允许用裁判自己的外部知识替代题目中的知识快照；
- 对隐含覆盖保持谨慎，必须能指出回复中的证据；
- 专业或业务事实与题目冲突时，优先判定事实错误；
- 只评价当前题要求，不奖励无关扩展。

## 6. 分数解释

| 分数 | 解释 |
|---:|---|
| 90—100 | 可直接用于该节点，只有轻微表达优化空间 |
| 75—89 | 基本合格，存在局部能力遗漏 |
| 60—74 | 勉强可用，需要人工补充或限制使用 |
| 41—59 | 明显不合格，存在关键任务缺失 |
| 0—40 | 触发严重错误或主要任务失败 |

## 7. 汇总指标

至少输出：

- 全集平均分与中位数；
- 单轮、多轮、边界三个子集的平均分；
- 按`primary_capability`统计平均分；
- 按`source_case`统计平均分；
- 严重错误率；
- 每类`must_not`触发次数；
- 低于60分的题目列表；
- 同一模型不同版本的分数变化。
