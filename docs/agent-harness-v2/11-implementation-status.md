## Agent 自主权与系统硬边界

Agent 自主决定每轮商业判断、关系目的、表达方式、工具组合、资料时机、商品卡片时机和专项唤醒。系统只硬控以下内容：

- 商品、价格、库存、订单、物流、权益、资料引用和优惠结果必须来自真实工具。
- `prepared`、`queued` 不得表述为 `sent`；未被 Agent 放入最终回复包的预备卡片不会发送。
- 退款、赔偿、改价、改订单、客户要求人工等授权动作必须转人工。
- 客户隔离、真实引用、参数校验、近期重复资料、防内部状态泄露和未核实促销话术。
- 新好友开场必须完成“小兰和萧岚苑身份 + 品牌图片 + 盆数与主要品种问题”的语义结构。
- 微信队列顺序、依赖、限速、重试、状态回写和技术不可发送状态。

问题数量、编号、项目符号、Markdown 和普通引号属于质量提示，不再阻止安全回复发送。运行时只允许未核实事实、权限、真实引用、发送状态、内部泄露和固定开场缺失等硬违规触发一次定向重写；修复失败时转人工，不再用通用销售兜底覆盖模型原回复。

普通表情、短句、“嗯”“好的”等不按垃圾信息丢弃，会交给 Agent 结合上下文理解；只过滤明确的传输占位、系统事件和无法形成客户语义的 UI 噪声。

默认销售思路已经调整为“先收集足以匹配的客户事实，再主动推荐”：新客户先理解来意，只补真正会改变下一步的信息，同时提供真实帮助并自然塑造团队价值。问题不是默认结尾；一旦现有事实已具备商业充分性，就停止症状细节盘问，转入回答、团队价值、陪伴服务或真实商品。新好友身份、普通兰花话题或索要资料本身不会触发商品或资料发送；当客户需求和关键条件已经足以解释适配理由时，即使客户没有说固定购买口令，Agent 也会主动查询并推荐。资料只有在能说明匹配、释放目的和后续动作时才发送，发送后继续挖需或转入产品推荐。这是核心提示和渐进披露经验，不是新增阶段机、关键词路由或固定字段表单。

新好友第一轮固定收集当前盆数和主要品种。后续由 Agent 结合盆数、痛点、养兰时间、失败经历和持续指导缺口判断推陪伴服务还是具体产品；盆数与痛点已经足够时停止横向盘问。L1-L6、盆数和品种通过 `customer.tag` 以客户本轮原话证据写入，只作为可修正客户事实；抖音已购继续由订单截图核验，微信已购在真实已付款订单查询成功后自动写入，两个已购标签不允许模型推断。

## 每日触达

- 技术上可发送且当天没有真实 `sent` 的客户，会生成持久化每日唤醒。
- 当天普通会话回复与人工消息均计入；同一逻辑回复包的多条消息只算一次触达。
- 普通客户每天最多两次主动触达；明确文字拒绝后降低为每天一次，但不永久放弃。
- 人工会话中不抢发，由系统提醒当前负责人完成今日触达。
- 唤醒任务带幂等键、处理租约、最多三次尝试和 15 分钟重试；发送前若客户产生新消息，会取消陈旧内容并重新判断。

## Git 回退

优先使用可逆提交：

1. 找到本次 Harness V2 提交。
2. 在 `main` 上执行 `git revert <提交号>` 并正常推送。
3. 重新部署回退后的 `main`。

若需要完整恢复替换前版本，可从标签 `pre-agent-harness-v2` 构建部署。不要 force-push，不要对生产工作树执行 `reset --hard`。回退代码不会自动删除新 Agent 创建的表；这些新增表对旧版本无调用影响。
