# Service Agent 与首单经验隔离入口

这组文档记录萧岚苑 Agent Harness 的业务决定、已落地架构和维护方式。2026-08-13 当前代码的默认 SOP 已从首单成交切换为老客户服务；原首单 Prompt 和经验保留为隔离作用域，不再默认加载。该改动尚未部署生产，状态见 [实施状态与运维交接](11-implementation-status.md)。

## 已确认的总方向

- 生产默认使用服务 SOP：先解决客户问题、履行会员服务并维护关系，再通过少量有效追问积累客户事实。
- 会员权益和品牌价值应承接本轮真实帮助自然呈现；复购是出现真实选购需求后的后续结果，不是养护问答的默认结尾。
- 原首单 SOP、首单开场、陪伴服务优先、痛点转服务和试成交经验完整保留，但只有明确 `sop_scope=first_order` 时才可加载。
- `capability.search` 按 `service / first_order / shared` 作用域过滤经验，服务流程不能误取首单经验。
- Agent 自主选择商品、资料、订单、记忆、唤醒和人工接管等工具；系统负责事实、权限、引用和执行安全。
- 服务关系维护优先使用问题回访、季节养护、品种故事、辨兰知识和会员内容；朋友圈“每天发干货”不等同于每天强制私聊。
- 微信入站、出站队列、限速、重试、状态回写和客户隔离等基础设施继续硬性保留。
- 新架构直接替换现有主决策链，不做影子运行或灰度双轨；旧实现通过 Git 历史和基线标记保留回退能力。
- 动态价格、库存、优惠结果、权益、订单和发送状态必须来自真实工具，不能从历史话术或模型推测中继承。

## 文档使用方式

- 按下面顺序阅读；后续实现和评测都应引用这些文档，而不是重新发明销售流程。
- 新增经验、产品事实或资料时，放入对应文档或权威业务库，不向 Sales Core 持续堆补丁。
- 仍未具备权威数据源的动态事实保持未知，由工具或人工核实，不能为了填满而猜测。
- 不要在文档中填写密钥、真实客户隐私、登录信息或未脱敏订单数据。

## 哪些内容不需要你提供

以下内容由系统实现并验证，不要求业务方设计技术细节：

- Agent 循环、上下文装配和渐进式披露机制。
- 工具 Schema、稳定引用、参数校验、权限和失败状态。
- 微信消息入站合并、去重、排队、限速、依赖顺序、重试和状态回写。
- 数据库结构、任务租约、幂等、日志和监控。
- 离线评测执行器、Git 基线、回滚脚本和上线监控。

你需要提供的是业务真相、销售经验和边界；系统负责把这些可靠地交给 Agent，并约束真实执行。

## 共同使用的分类

维护时，尽量把每条内容放入正确类型：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 核心目标 | Agent 始终理解的方向 | 长期信任前提下推进成交 |
| 柔性经验 | 依赖客户和语境，由 Agent 判断 | 通常先理解问题，再考虑发资料 |
| 业务事实 | 必须来自权威数据源 | 商品价格、库存、订单状态 |
| 硬边界 | 不允许模型自行突破 | 不编造优惠，不联系已退订客户 |
| 基础设施 | 系统强制执行 | 微信发送排队、限速、幂等 |

判断方法：依赖语境、关系和时机的，优先写成柔性经验；涉及真实性、权限、客户权益、
不可逆动作或通信稳定性的，写成硬边界或基础设施。
