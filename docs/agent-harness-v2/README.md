# Sales Agent Harness V2 填写入口

这组文档用于共同确定下一版 Sales Agent Harness。当前阶段只收集业务输入和确认架构，
不会据此自动修改现有业务代码。当前所有文档已经预填写一版，可以直接修改，不需要从空白开始。

## 预填写内容怎么看

- “当前确认”来自本轮方向讨论，可以直接改成你更准确的表达。
- “当前现状”来自仓库已有代码、配置或业务文档，用于避免重复设计。
- 其他具体答案是建议草案，代表一版可实施的默认选择，不代表已经成为业务事实。
- 动态价格、库存、权益、订单和效果承诺没有从历史话术中抄成事实，仍要求以真实工具为准。

## 怎么填写

- 按下面的顺序一次填写一份，不需要一次全部完成。
- 搜索 `【建议草案】` 和 `【请修改】` 即可找到最值得你审阅的位置。
- 已经讨论清楚的内容以“当前草案”预填；正确就保留，不正确直接修改。
- 不确定的内容填写“暂不确定”，不要为了填满而猜测。
- 不要在文档中填写密钥、真实客户隐私、登录信息或未脱敏订单数据。

## 哪些内容不需要你提供

以下内容由系统实现并验证，不要求业务方设计技术细节：

- Agent 循环、上下文装配和渐进式披露机制。
- 工具 Schema、稳定引用、参数校验、权限和失败状态。
- 微信消息入站合并、去重、排队、限速、依赖顺序、重试和状态回写。
- 数据库结构、任务租约、幂等、日志和监控。
- 评测执行器、影子运行、灰度和回滚实现。

你需要提供的是业务真相、销售经验和边界；系统负责把这些可靠地交给 Agent，并约束真实执行。

## 共同使用的分类

填写时，尽量把每条内容放入正确类型：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 核心目标 | Agent 始终理解的方向 | 长期信任前提下推进成交 |
| 柔性经验 | 依赖客户和语境，由 Agent 判断 | 通常先理解问题，再考虑发资料 |
| 业务事实 | 必须来自权威数据源 | 商品价格、库存、订单状态 |
| 硬边界 | 不允许模型自行突破 | 不编造优惠，不联系已退订客户 |
| 基础设施 | 系统强制执行 | 微信发送排队、限速、幂等 |

判断方法：依赖语境、关系和时机的，优先写成柔性经验；涉及真实性、权限、客户权益、
不可逆动作或通信稳定性的，写成硬边界或基础设施。
