# 09 微信消息队列与输入处理

这份文档确认现有微信通道基础设施。它不属于销售风控，不决定 Agent 说什么；它负责安全稳定地收发消息。

## 已确认保留的当前能力

从当前实现确认，以下能力保留：

- 易云回调快速入队，不在回调请求内直接完成完整 AI 和发送链路。
- 按消息 ID 去重，避免供应商重试导致重复处理。
- 同一会话的连续入站消息合并后再交给 Agent。
- 出站消息统一进入数据库队列。
- 同一回复包中的文字、图片、视频、商品或资料卡片保持依赖顺序。
- 按微信账号控制发送频率和消息间隔。
- 发送失败重试，超过次数后标记失败。
- 记录 queued、sent、failed、cancelled 等状态并回写会话消息。
- 客户在等待期内发来新消息时，可以取消已经失去语境的服务跟进。
- 人工接管或已解决状态继续保持现有权威性。

## 输入处理

建议只硬过滤技术垃圾，不过滤低信息量的人类表达。

| 输入 | 处理建议 | 你的决定 |
| --- | --- | --- |
| 空消息、平台心跳、重复回调 | 系统直接过滤 |  |
| 无法解析的附件 | 变成明确的“附件解析失败”事件 |  |
| 单独的“嗯、哈哈、好的” | 保留给 Agent 结合上下文判断 |  |
| Emoji | 保留语义，不作为独立意图规则 |  |
| 表情包 | 有视觉能力时生成简短描述，否则记录为表情包 |  |
| 客户图片 | 视觉理解后连同原消息交给 Agent |  |
| 语音 | 转写并保留转写置信度 |  |
| 视频 | 提取可用描述；不足时让 Agent 自然说明 |  |
