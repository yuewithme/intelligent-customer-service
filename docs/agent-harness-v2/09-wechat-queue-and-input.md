# 09 微信消息队列与输入处理

这份文档确认现有微信通道基础设施。它不属于销售风控，不决定 Agent 说什么；它负责安全稳定地收发消息。

## 已确认保留的当前能力

从当前实现确认，以下能力保留：

- 易云回调快速入队，不在回调请求内直接完成完整 AI 和发送链路。
- 按消息 ID 去重，避免供应商重试导致重复处理。
- 同一会话的连续入站消息合并后再交给 Agent。
- 出站消息统一进入数据库队列。
- 同一回复包中的文字、图片、视频、商品或资料卡片保持依赖顺序。
- 按微信账号控制发送频率和消息间隔。
- 发送失败重试，超过次数后标记失败。
- 记录 queued、sent、failed、cancelled 等状态并回写会话消息。
- 客户在等待期内发来新消息时，可以取消已经失去语境的具体回复包；新消息产生的正常回复可以计入当天触达。
- 人工接管或已解决状态继续保持现有权威性。

## 当前技术默认值

直接替换版本沿用当前代码和示例配置中的以下默认值，未来可通过独立配置调整，不交给 Agent 控制。

| 参数 | 当前默认值 | 作用 | 最终决定 |
| --- | --- | --- | --- |
| 入站安静窗口 | 5 秒 | 等待客户连续消息后合并 | 原样保留，单独评测短消息合并体验 |
| 单批最长等待 | 15 秒 | 避免客户不断输入导致永不处理 | 原样保留 |
| 单账号发送上限 | 30 条 / 分钟 | 微信通道保护 | 原样保留，不交给 Agent 调整 |
| 最小发送间隔 | 2.1 秒 | 单账号消息间隔 | 原样保留 |
| 最大发送间隔 | 3.0 秒 | 普通出站随机间隔上限 | 原样保留 |
| 回复初始抖动 | 0 到 2 秒 | 避免所有回复固定时刻发送 | 原样保留 |
| 新好友开场间隔 | 同包 8 到 15 秒，跨客户 6 到 10 秒 | 降低连续开场发送的微信风险 | 使用独立持久化开场队列 |
| Worker 轮询 | 1 秒 | 队列扫描频率 | 原样保留 |
| 发送失败重试 | 当前最多 2 次，间隔 30 秒 | 临时失败恢复 | 原样保留；最终失败必须进入状态和监控 |

微信通道的其他硬约束：

- 所有业务模块继续统一调用微信出站网关，不允许 Agent 或新工具直接调用易云文本、图片、视频和小程序发送接口。
- 新好友开场固定为“Agent 自我介绍 + 品牌图片 + 从客户收益出发询问当前盆数和主要品种”，具体文字由 Agent 自然生成；盆数和品种放在一个自然关联问句中，三条消息使用独立的持久化开场节奏、依赖链、失败暂停和恢复机制。
- 同一逻辑回复包使用依赖链保序；前置卡片或消息失败时，依赖它的“我已经发给您”类承接消息不得继续发送。
- 图片和视频优先使用现有微信素材库与 `material_id`；素材过期时进入 `waiting_material`，不降级为重复上传或假装发送。
- 普通 Agent 回复在 `human_active` 时不插入人工会话；服务中固定素材触达按独立已确认节奏运行。
- 平台拉黑、退订、通道 `forbidden`、账号不可用或客户明确拒绝时不得绕过网关发送服务中素材。

## Agent 与队列的接口

Agent 输出一个逻辑回复包：

```json
{
  "purpose": "本轮回复目的",
  "messages": [
    {"type": "text", "content": "自然回复"},
    {"type": "material_card", "material_ref": "真实资料引用"},
    {"type": "text", "content": "承接资料的下一句话"}
  ]
}
```

队列负责顺序、间隔、排队、重试和状态；Agent 不接触底层限速参数。

普通回复中，Agent 可以自由决定同一回复包中的消息数量和组合，但由表达经验控制简洁度、由系统设置合理技术上限。Agent 决定“文字、卡片、图片如何形成自然回复”；运行时保留 Agent 明确给出的消息单元，并将单个文字中的明确空行语义段标准化为独立消息；队列决定“顺序、间隔和真实送达”。新好友开场是结构例外，图片由网关固定插入，Agent 只生成前后的自然文字。

一个逻辑回复包技术上限为 5 个消息单元，普通对话默认 1 到 2 个。超过 5 个时要求 Agent 重新压缩或改为更合适的资料载体；购买后批量交付资料作为独立业务任务处理，不挤进普通回复包。

## 服务中素材触达调度

- 只为带有效“服务中”标签且通道可用的客户创建 07:00、10:00、14:00 三个幂等任务。
- worker 只查询 `service_material_touch` 类型，不处理历史普通触达或专项唤醒任务。
- 媒体转换成功后，已审核文案和图片或视频按依赖顺序整包入队；全部真实 `sent` 后任务才完成。
- 服务标签移除、客户明确拒绝、平台禁止发送或账号不可用时取消或技术跳过，不绕过网关。

## 输入处理

只硬过滤技术垃圾，不过滤低信息量的人类表达。

| 输入 | 最终处理 | 决定 |
| --- | --- | --- |
| 空消息、平台心跳、重复回调 | 系统直接过滤 | 采用，属于技术垃圾 |
| 无法解析的附件 | 变成明确的“附件解析失败”事件 | 采用，让 Agent 知道不是客户没发内容 |
| 单独的“嗯、哈哈、好的” | 保留给 Agent 结合上下文判断 | 采用，不做固定意图映射 |
| Emoji | 保留语义，不作为独立意图规则 | 采用 |
| 表情包 | 有视觉能力时生成简短描述，否则记录为表情包 | 采用，保留“不确定”状态 |
| 客户图片 | 视觉理解后连同原消息交给 Agent | 采用，原图引用和视觉描述同时保留 |
| 语音 | 转写并保留转写置信度 | 采用，低置信度时允许自然确认 |
| 视频 | 提取可用描述；不足时让 Agent 自然说明 | 采用，不虚构没有看到的画面 |

其他输入规则：

- 微信账号登录、掉线、好友变更等供应商事件进入系统事件通道，不作为客户消息送给 Sales Agent。
- 自己发送的回显消息、供应商重试和同一 `msgId` / `newMsgId` 回调只记录一次，不触发重复回复。
- 无法识别的消息类型保留类型、来源和失败原因；如果可能包含客户意图，Agent 可以自然请求客户改用文字、图片或重新发送。

## 状态真实性

进入队列不等于已经发送。只有收到真实成功结果，客户工作区才能记录“已发送”；失败或取消必须让 Agent 在下一轮看见。

`planned` 和 `queued` 只能说明系统准备发送；服务中素材整包只有全部真实 `sent` 才算完成。`failed`、`cancelled` 和素材转换失败必须如实回写，不能被描述成已发送。
