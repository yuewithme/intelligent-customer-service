# 07 客户记忆与服务中触达

客户记忆用于保存有证据的稳定事实、问题、购买状态、资料关系、承诺和联系偏好，不作为固定销售阶段或自动跟进路由。

## 客户工作区

| 分类 | 示例 | 规则 |
| --- | --- | --- |
| 稳定事实 | 地区、养兰经验、环境、盆数、品种 | 必须有客户或授权来源；被纠正时更新 |
| 可信购买标签 | 抖音已购、微信已购 | 只能由已验证截图或真实已付款订单写入 |
| 当前问题与待办 | 黄叶、查订单、等到货 | 保留到完成、取消或过期 |
| 资料与商品关系 | 发过、推荐过、买过 | 以真实查询和发送状态为准 |
| 顾虑与联系偏好 | 价格顾虑、明确拒绝 | 只记录明确表达；拒绝会阻止服务中自动触达 |
| 关系摘要 | 本轮进展和后续值得延续的点 | 滚动更新，不覆盖底层证据 |

模型推测、无关隐私、访问密钥、动态价格库存和仅由助手自己说出的内容不得写成客户事实。

## 自动触达边界

- 普通客户不运行每日触达，也不向 Agent 暴露自动唤醒工具。
- 只有带有效“服务中”标签的客户进入固定三时段素材触达。
- 触达内容由已审核素材库提供，不调用 Sales Agent 临时生成营销消息。
- 服务标签移除、客户明确拒绝、联系人或发送账号不可用时取消或跳过。
- 历史非服务中任务保留数据库记录但永不被 worker 读取，若遗留消息到达发送前校验也会被阻断。

## 服务中任务状态

服务中任务按业务时区生成 07:00 名品故事、10:00 养护科普、14:00 话题种草三个幂等任务。媒体必须先转换成功，随后文案和图片或视频按依赖顺序整包入队；整包全部真实 `sent` 后任务才标记完成。

`planned`、`queued`、`sent`、`failed`、`cancelled` 和技术跳过状态必须如实记录。队列负责顺序、间隔、限速和最终状态回写，业务代码不得绕过。
