# 07 客户记忆与跟进

客户记忆不是一组销售阶段字段，而是让 Agent 知道这个人发生过什么、当前在意什么、我们承诺过什么，
以及还有什么值得处理。

## Agent 每轮应该看到的客户工作区

以下结构结合当前 Memory 2.0 的“事实、经历、工作状态和证据”。表中保留期限作为实现默认值；已有隐私或业务政策优先。

| 分类 | 示例 | 是否需要 | 保留多久 / 更新方式 |
| --- | --- | --- | --- |
| 客户稳定事实 | 地区、养兰经验、家中环境 | 需要 | 长期保留，必须有客户或授权来源；被纠正时版本化更新 |
| 当前问题 | 黄叶、烂根、想选新手品种 | 需要 | 作为工作状态保留到解决、放弃或明显过期；同时沉淀有证据的经历 |
| 判断所需信息 | 已知光照，仍缺浇水频率 | 需要 | 当前任务有效，任务结束后不继续当作长期画像 |
| 产品与服务关系 | 看过、推荐过、买过、明确不适合 | 需要 | 查看和推荐可阶段性衰减；购买必须来自订单系统并长期留痕 |
| 资料关系 | 发过什么、为什么发、是否反馈 | 需要 | 至少覆盖重复发送控制和后续承接周期；以真实 sent 状态为准 |
| 顾虑 | 价格、效果、信任、时间、家人意见 | 需要 | 只记录客户明确表达或高置信证据；问题解决后标记失效，不永久贴标签 |
| 承诺 | 客户说晚点发图，我们答应帮他看 | 需要 | 保留到完成、取消或过期；保留相关事件作为经历 |
| 待办 | 查订单、等到货、回访恢复情况 | 需要 | 保留到完成、失败、取消或转人工 |
| 联系偏好 | 适合时间、客户文字拒绝、平台禁止发送状态 | 必须 | 文字拒绝触发降频；平台拉黑、退订或 `forbidden` 触发技术跳过，状态变化时版本化更新 |
| 触达账本 | 每日 `sent` 次数、发送者、主题、资料、商品和客户反应 | 必须 | 按自然日计数，历史用于避免重复；只有真实发送成功写入 |
| 关系摘要 | 本轮关系进展和下一次值得延续的点 | 需要 | 滚动摘要，不覆盖底层证据；每次重要互动后更新 |

## 记忆原则

最终记忆原则：

- 哪些信息非常值得长期记住：地区和环境、养兰经验、稳定偏好、长期痛点、明确购买兴趣、真实购买、联系偏好、重要承诺和已发生的关键销售 / 售后经历。
- 哪些信息只对当前会话有效：本轮临时选择、尚未确认的症状假设、当前缺少的信息、短暂情绪和一次性操作参数。
- 哪些信息不应该保存：模型无证据推测、无关隐私、完整敏感字段、访问密钥、与服务无关的聊天内容，以及仅由助手自己说出却被误当成客户事实的信息。
- 客户纠正信息后如何处理：追加纠正事件并生成新版本；旧事实保留审计关系但退出当前有效上下文，不静默覆盖证据。
- 推测和客户明确事实是否需要区分：必须区分。客户明确表达、业务系统事实、人工确认和模型推测拥有不同来源与可信度。
- 订单、价格等动态事实是否只保存引用和查询时间：是。当前回复前重新查询；记忆不能替代商品和订单工具。

## 跟进与唤醒的职责

`wakeup.schedule` 只安排未来重新判断的时机，不提前固定未来发送的话术。唤醒后，Agent 重新读取最新客户工作区，
决定本次触达的内容、延后某条专项提醒、取消过时任务或转人工；只要客户技术上仍可发送，每日真实触达义务不被取消。

唤醒是一条“未来重新思考”的任务，不是一条延迟发送的固定话术。唤醒时必须重新读取新消息、购买、通道状态、人工接管、资料发送、订单变化和今日触达计数，再决定内容与工具。对于技术上可发送且今天尚未完成触达的客户，系统不能允许 Agent 永久取消每日业务义务。

## 值得唤醒的业务事件

| 事件 | 为什么值得重新判断 | 默认时间范围 | 唤醒时要看什么 | 哪些情况取消专项提醒 |
| --- | --- | --- | --- | --- |
| 客户答应之后发照片 | 照片可能让诊断或建议继续 | 未指定时在 12 到 24 小时内进入下一次触达判断 | 是否已发图、问题是否仍存在、是否已经人工处理 | 已发图或问题解决时取消这条专项提醒，但每日关系触达仍继续 |
| 客户说过几天考虑 | 有真实顾虑或决策时间 | 尊重客户给出的决策时间，同时 12 到 24 小时内仍完成一次非机械触达 | 是否购买、顾虑、近期新消息、当前商品事实 | 已购买后切换为服务目的；明确拒绝后降为每天一次，不永久取消 |
| 发送资料后等待反馈 | 资料可能产生新的问题或购买信号 | 下一次每日触达时重新判断，通常不超过 24 小时 | 是否真实 `sent`、是否反馈、资料目的、近期是否已问过同一问题 | 未发送成功时不按已交付承接；客户已回复则当天回复计入触达 |
| 推荐商品但暂未购买 | 可能需要解决顾虑或重新匹配 | 默认 12 小时内重新判断，所有跟进不超过 24 小时 | 商品是否仍在售、客户顾虑、是否已有替代方案 | 已购买后切换服务；商品下架时重新匹配；拒绝后降频 |
| 商品到货后的养护关怀 | 到货是高价值服务节点 | 请参考服务SOP | 订单和签收、是否已发送单品手册、异常反馈 | 未签收、退款、人工售后已接管 |
| 客户持续沉默 | 仍需通过新角度经营需求和购买理由 | 每天至少一次真实触达，首次通常在 12 小时内 | 最近触达主题、资料和商品是否重复、历史拒绝、购买状态、是否有新的关系目的 | 通道不可发送时技术跳过；不能因连续无响应永久取消 |
| 服务承诺或待办到期 | 避免我们忘记已答应客户的事 | 按承诺时间，且不得超过 24 小时没有任何关系触达 | 是否完成、负责人、工具结果 | 已完成时取消专项提醒，但继续日常关系经营 |

每日触达规则：

1. 所有跟进间隔不得超过 24 小时；犹豫、等待反馈、未购买和沉默等软拒绝，默认在 12 小时内重新触达。
2. 普通客户每天至少一次、最多两次真实发送；明确拒绝后降低为每天一次。避免在 23:00 到次日 08:00 主动发送。
3. 当天客户主动发消息后的 Agent 正常回复，以及人工当天发送的有效消息，都计入当天触达；不为完成计数重复插入自动消息。
4. 客户未回复时继续每日循环唤醒并真实发送。每次重新选择目的和内容，可以推进流程、理解顾虑、介绍商品、申请福利、发送养护经验或资料，但不能预写固定话术。
5. 已购客户优先触达养护经验、到货关怀、订单服务和长期关系；仍可结合真实需求识别复购机会。
6. 平台拉黑、退订、通道 `forbidden` 或账号不可用时记录为技术不可发送并跳过；通道恢复或客户重新主动联系后恢复判断。

## 跟进经验

- 什么样的跟进让客户觉得有价值：延续他之前的具体问题、带来新的判断或资料、兑现我们的承诺、基于真实事件提醒，并且让客户容易继续回答。
- 什么样的跟进像骚扰或机械催单：重复问“考虑得怎么样”、没有新价值、忽略客户已经拒绝、固定频率群发、重新介绍已说过的全部卖点。
- 软拒绝后最重要的判断是什么：这是价格、信任、适配、时机、选择困难，还是礼貌结束；默认软拒绝后仍继续推进，但下一次触达目的和力度应随判断改变。
- 客户不回复时，应关注哪些上下文：最后一次对话是否需要回复、我们是否已经给了足够信息、客户是否承诺某件事、上次触达时间、资料 / 卡片是否真实送达、是否存在新价值。
- 哪些客户会永久退出每日判断：没有。只有当前技术上不可发送的客户跳过实际发送；他们仍保留关系记录，等待通道恢复或客户重新联系。
- 哪些事件即使客户未回复也必须服务性提醒：所有可发送客户都必须保持每日触达，可使用养护经验、品种介绍、真实商品、福利申请、推进流程或挖掘需求等不同关系目的。

## 系统强制部分

以下由系统负责，不需要 Agent 自行计算：

- 唤醒任务幂等、持久化、到期触发和取消。
- 按业务时区（默认 `Asia/Shanghai`）计算自然日，统计当天真实 `sent` 次数并生成未完成触达任务。
- 普通客户每日最多两次、明确拒绝客户每日一次，以及 23:00 到 08:00 的主动发送时间保护。
- 客户回复、Agent 回复和人工消息的同日去重计数；人工接管时不插入重复自动消息。
- 通道拉黑、平台退订、`forbidden` 和账号不可用状态的技术跳过与恢复。
- 微信通道限速和实际发送排队。
- `planned`、`queued`、`sent`、`failed`、`cancelled` 状态记录。
