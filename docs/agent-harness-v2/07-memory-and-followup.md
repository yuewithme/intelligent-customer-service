# 07 客户记忆与跟进

客户记忆不是一组销售阶段字段，而是让 Agent 知道这个人发生过什么、当前在意什么、我们承诺过什么，
以及还有什么值得处理。

## Agent 每轮应该看到的客户工作区

以下结合当前 Memory 2.0 的“事实、经历、工作状态和证据”结构预填写。具体保留期限是建议值，应由隐私和业务政策最终确认。

| 分类 | 示例 | 是否需要 | 保留多久 / 更新方式 |
| --- | --- | --- | --- |
| 客户稳定事实 | 地区、养兰经验、家中环境 | 需要 | 长期保留，必须有客户或授权来源；被纠正时版本化更新 |
| 当前问题 | 黄叶、烂根、想选新手品种 | 需要 | 作为工作状态保留到解决、放弃或明显过期；同时沉淀有证据的经历 |
| 判断所需信息 | 已知光照，仍缺浇水频率 | 需要 | 当前任务有效，任务结束后不继续当作长期画像 |
| 产品与服务关系 | 看过、推荐过、买过、明确不适合 | 需要 | 查看和推荐可阶段性衰减；购买必须来自订单系统并长期留痕 |
| 资料关系 | 发过什么、为什么发、是否反馈 | 需要 | 至少覆盖重复发送控制和后续承接周期；以真实 sent 状态为准 |
| 顾虑 | 价格、效果、信任、时间、家人意见 | 需要 | 只记录客户明确表达或高置信证据；问题解决后标记失效，不永久贴标签 |
| 承诺 | 客户说晚点发图，我们答应帮他看 | 需要 | 保留到完成、取消或过期；保留相关事件作为经历 |
| 待办 | 查订单、等到货、回访恢复情况 | 需要 | 保留到完成、失败、取消或转人工 |
| 联系偏好 | 适合时间、是否接受主动跟进 | 必须 | 长期有效直到客户纠正；退订和拒绝具有最高优先级 |
| 关系摘要 | 本轮关系进展和下一次值得延续的点 | 需要 | 滚动摘要，不覆盖底层证据；每次重要互动后更新 |

## 记忆原则

【建议草案】

- 哪些信息非常值得长期记住：地区和环境、养兰经验、稳定偏好、长期痛点、明确购买兴趣、真实购买、联系偏好、重要承诺和已发生的关键销售 / 售后经历。
- 哪些信息只对当前会话有效：本轮临时选择、尚未确认的症状假设、当前缺少的信息、短暂情绪和一次性操作参数。
- 哪些信息不应该保存：模型无证据推测、无关隐私、完整敏感字段、访问密钥、与服务无关的聊天内容，以及仅由助手自己说出却被误当成客户事实的信息。
- 客户纠正信息后如何处理：追加纠正事件并生成新版本；旧事实保留审计关系但退出当前有效上下文，不静默覆盖证据。
- 推测和客户明确事实是否需要区分：必须区分。客户明确表达、业务系统事实、人工确认和模型推测拥有不同来源与可信度。
- 订单、价格等动态事实是否只保存引用和查询时间：是。当前回复前重新查询；记忆不能替代商品和订单工具。

## 跟进与唤醒的职责

`wakeup.schedule` 只安排未来重新判断的时机，不提前固定未来发送的话术。唤醒后，Agent 重新读取最新客户工作区，
决定发送、延后、取消或转人工。

【建议草案】保留这个原则。

回答：唤醒是一条“未来重新思考”的任务，不是一条延迟发送的固定话术。唤醒时必须重新读取新消息、购买、退订、人工接管、资料发送和订单变化，再决定动作。

## 值得唤醒的业务事件

| 事件 | 为什么值得重新判断 | 建议时间范围 | 唤醒时要看什么 | 哪些情况自动取消 |
| --- | --- | --- | --- | --- |
| 客户答应之后发照片 | 照片可能让诊断或建议继续 | 客户未指定时建议 24 到 48 小时 | 是否已发图、问题是否仍存在、是否已经人工处理 | 已发图、问题已解决、客户拒绝或转人工 |
| 客户说过几天考虑 | 有真实顾虑或决策时间 | 优先按客户说的时间；未说明时建议 3 到 7 天 | 是否购买、顾虑、近期新消息、当前商品事实 | 已购买、明确拒绝、退订、商品失效 |
| 发送资料后等待反馈 | 资料可能产生新的问题或购买信号 | 建议 2 到 5 天，不要求每份资料都跟进 | 是否真实 sent、是否打开 / 反馈、资料目的 | 未发送成功、客户已回复、明确不需要 |
| 推荐商品但暂未购买 | 可能需要解决顾虑或重新匹配 | 建议 1 到 3 天；高投入决策可更长 | 商品是否仍在售、客户顾虑、是否已有替代方案 | 已购买、商品下架、明确拒绝、投诉 |
| 商品到货后的养护关怀 | 到货是高价值服务节点 | 以真实物流签收事件为准，建议签收后 1 天内重新判断 | 订单和签收、是否已发送单品手册、异常反馈 | 未签收、退款、人工售后已接管 |
| 客户长期沉默但存在合适福利触点 | 新资料、季节提醒或真实活动可能重新创造价值 | 建议至少间隔 14 到 30 天，并受联系偏好约束 | 是否有新的具体价值、上次触达、历史拒绝和购买状态 | 没有新价值、退订、连续无响应达到上限 |
| 服务承诺或待办到期 | 避免我们忘记已答应客户的事 | 按承诺时间 | 是否完成、负责人、工具结果 | 已完成、取消或人工接管 |

## 跟进经验

【建议草案】

- 什么样的跟进让客户觉得有价值：延续他之前的具体问题、带来新的判断或资料、兑现我们的承诺、基于真实事件提醒，并且让客户容易继续回答。
- 什么样的跟进像骚扰或机械催单：重复问“考虑得怎么样”、没有新价值、忽略客户已经拒绝、固定频率群发、重新介绍已说过的全部卖点。
- 软拒绝后最重要的判断是什么：这是价格、信任、适配、时机、选择困难，还是礼貌结束；证据不足时宁可收住，不强行定义。
- 客户不回复时，应关注哪些上下文：最后一次对话是否需要回复、我们是否已经给了足够信息、客户是否承诺某件事、上次触达时间、资料 / 卡片是否真实送达、是否存在新价值。
- 哪些客户不值得继续营销触达：明确退订或拒绝、投诉未解决、连续多次触达无回应且没有新价值、产品明显不适配、联系身份或权限不清楚。
- 哪些事件即使客户未回复也必须服务性提醒：订单履约必要通知、客户明确约定的提醒、人工售后要求的事项；具体范围仍以当前业务政策和平台规则为准。

## 系统强制部分

以下由系统负责，不需要 Agent 自行计算：

- 唤醒任务幂等、持久化、到期触发和取消。
- 退订、人工接管或客户新消息后的任务失效规则。
- 微信通道限速和实际发送排队。
- planned、queued、sent、failed、cancelled 状态记录。

## 【请修改】你只需要重点审阅

- 各类唤醒时间范围是否符合真实销售节奏。
- 连续不回复多少次后停止主动营销，以及多久后才能出现新的福利触点。
- 哪些购买后服务消息属于必须通知，哪些仍需要客户授权。
