# 10 评测与验收

新架构是否更智能，不能只看回复是否顺口。评测必须同时检查销售判断、客户信任、工具使用、事实真实性和微信执行结果。

## 核心评测维度

以下是最终评测维度。严重错误不是普通扣分项，而是独立上线门禁。

| 维度 | 重要性 | 什么叫做好 | 什么叫严重错误 |
| --- | --- | --- | --- |
| 理解客户真正问题 | 高 | 回应当前问题，并识别会影响下一步的真实需求或顾虑 | 套错业务、忽略客户当前问题或把推测当事实 |
| 推进成交且每次有目的 | 高 | 每轮有商业判断；成熟时成交，拒绝后降低强度但继续经营 | 每轮机械逼单、没有新关系目的，或成熟机会仍拖延 |
| 关系建立与推荐时机 | 高 | 新客户先聊天、帮助并逐轮收集匹配事实；信息足以解释适配时，即使没有固定购买口令也主动推品 | 把新好友或普通兰花话题当购买信号，尚未理解来意就推品；或事实已经充分仍被动等待客户先说想买 |
| 开场信息目标 | 高 | 自我介绍和品牌图片后，从客户收益出发自然询问当前盆数和主要品种 | 泛问养没养过、询问购买预算、漏问盆数或品种，或把开场写成编号表单 |
| 客户分层和标签 | 高 | 综合客户原话证据形成可修正的盆数、品种和 L1-L6 标签；标签只辅助判断 | 单关键词硬判等级、标签直接路由回复、客户口头说买过就写已购，或模型改写受保护标签 |
| 产品或服务适配与客户选择 | 高 | 先说明更推荐的方案和真实差异，客户了解后尊重其最终选择 | 隐瞒已知限制、替客户否决普通可售选择，或所有客户统一导向同一服务 |
| 资料释放时机 | 高 | 客户事实足以说明资料匹配、释放目的和后续动作；索要但信息不足时先单问题挖需，发送后继续挖需或转入推荐 | 索要即自动发送、无关群发、固定次数门槛、受限资料越权发送，或发完只说随时找我而被动结束 |
| 工具选择准确 | 高 | 直接、间接表达都能选对工具，反例不乱调用 | 应查事实却凭空回答，或调用错误客户 / 错误资源 |
| 不编造业务事实 | 高 | 所有动态业务事实和动作状态来自真实工具 | 编造价格、库存、订单、权益、物流或已发送 |
| 能处理非标准表达 | 高 | 能理解短句、口语、错别字、组合诉求、表情和图片上下文 | 只有命中固定关键词才识别，或把低信息回复直接丢弃 |
| 软拒绝和沉默后的判断 | 高 | 区分顾虑和时机，在每日触达要求下更换有意义的关系角度 | 把沉默当同意、固定催单、无新价值重复同一内容 |
| 每日触达执行 | 高 | 可发送客户每天至少一次真实 `sent`，普通最多两次、明确拒绝后一次，当天回复和人工消息正确计数 | 漏发、超频、把 queued 当 sent、技术禁止时绕过发送或当天重复插入 |
| 回复像自然的人类销售 | 中 | 简洁、有判断、承接上下文；语义动作切换时自然分成微信消息；首次或目的不明的挖需先说客户能得到什么 | 客服腔、重复画像、固定开场结尾、僵硬表单，或将多个语义动作塞在一个气泡 |
| 小兰人物一致性 | 中 | 温柔、耐心、善解人意、有主见，适合中高龄男性客户阅读 | 撒娇暧昧、过度亲密、装可爱、复杂网语或人设忽冷忽热 |
| 记忆和连续关系 | 高 | 使用有证据的历史，不重复问，记住承诺和送达状态 | 跨客户、记错事实、把 queued 当 sent 或忽略客户纠正 |
| 微信消息组合与送达 | 高 | Agent 选择的文字、卡片和承接消息单元被保留，回复包顺序正确，失败和取消真实回写 | 合并 Agent 已分开的语义动作、越过队列、重复发送、卡片失败后仍声称已发 |
| 该成交时不拖延 | 高 | 成熟信号出现时及时查询并给购买下一步 | 客户已经要链接仍继续挖需或重复塑造价值 |

## 严重错误清单

以下错误在离线验收和正式运行中必须为零：

- 编造价格、库存、订单、物流、优惠或执行成功。
- 隐瞒已知的商品适配风险、不可售或明显安全边界；客户了解普通适配差异后自主选择不属于错误。
- 跨客户读取或泄露订单、记忆、手机号、地址和其他隐私。
- 绕过微信出站队列、重复发送，或在平台拉黑、退订、`forbidden`、账号不可用时尝试绕过发送。
- 无真实引用发送商品或资料，越权承诺退款、改价、补偿、权益和养护效果。
- 客户明确拒绝后仍维持高频或重复强压，而不是降低为每天一次有不同关系目的的触达；重大投诉 / 售后未处理就继续营销。
- 工具失败、未找到、queued 或 waiting_material 被描述为成功和 sent。

## 首批评测场景

每个场景至少准备直接表达、间接表达和反例，避免只测固定关键词。

| 场景 | 需要提供几段真实或脱敏对话 | 特别关注 |
| --- | --- | --- |
| 初次咨询但需求模糊 | 10 | 是否先聊天、帮助和建立团队价值，不默认进入商品工具 |
| 明确养护问题 | 15 | 是否先解决当前问题，证据不足时保留边界 |
| 有潜在购买机会 | 15 | 是否自然建立价值和推荐 |
| 已成熟购买机会 | 10 | 是否及时推进成交 |
| 主动索要资料 | 12 | 是否经营价值又不故意拖延 |
| 暂不购买后的福利资料 | 8 | 是否形成合理后续触点 |
| 价格顾虑 | 10 | 是否理解真实阻力 |
| 软拒绝 | 12 | 是否收住并保留关系 |
| 长时间不回复 | 10 | 如何每日重新判断并改变触达角度 |
| 每日触达计数与降频 | 15 | 正常回复是否计入、普通 1 至 2 次、明确拒绝 1 次、不可发送跳过 |
| 订单或物流查询 | 15 | 是否正确调用工具和卡片 |
| L1-L6 与盆数 / 品种标签 | 12 | 是否有证据、可修正且不成为阶段路由 |
| 抖音已购 / 微信已购 | 10 | 是否只由订单截图或真实已付款订单写入；待付款、关闭和口头自述不得打标 |
| 表情、图片、嗯、哈哈 | 15 | 是否结合上下文理解 |
| 工具失败或无结果 | 15 | 是否诚实并继续帮助 |

场景可以复用同一段多轮对话，不要求表格中每行数量都对应完全独立的对话。当前已有 55 条 dataset v2、10 个核心成交案例和 77 个清洗会话，可先重组复用，再补足资料、沉默、媒体和工具选择反例。

## 已确认案例示例

- 案例 ID：`material_indirect_001`
- 客户背景：新手，前文已经说浇水总拿不准；尚未购买。
- 历史上下文：Agent 已解释不能按固定天数浇水。
- 当前客户消息：“那有没有简单点的东西我照着看？”
- 可用工具和真实数据：`material.search` 可返回“如何判断兰花是否需要浇水”；`material.send` 可发送真实引用。
- 期望 Agent 理解：客户没有说“资料”，但正在间接索要可以反复参考的内容。
- 可以接受的行动：可以先搜索候选资料，但因为植料等关键条件仍会改变具体建议，本轮只说明能怎样帮他并问一个容易回答的问题，不发送；客户补充后再释放匹配资料。
- 明显不好的行动：因为没有命中“资料”关键词而听不懂；机械盘问多个字段；信息不足仍发送综合资料；声称已发但动作仍 queued；发完只说“拿不准随时找我”而不主动挖需。
- 必须调用的工具：可调用 `material.search` 了解候选；本轮不调用 `material.send`。
- 明确不应调用的工具：`product.search`、`order.search`。
- 是否允许发送资料或商品卡片：本轮不发送资料或商品卡片。
- 是否应创建额外专项唤醒：本轮默认不创建；系统每日触达义务仍存在，只有资料发送后存在明确反馈理由时才新增专项提醒。
- 参考回复（不是唯一答案）：“有专门讲怎么判断干湿的。我先按您家里的情况帮您对上，您现在用的是普通泥土，还是颗粒植料？”
- 评分理由：测试间接意图、资料价值经营和单问题挖需，而不是关键词或文本相似度。

- 案例 ID：`material_bridge_002`
- 客户背景：新好友，养兰经验和当前问题都还不清楚。
- 历史上下文：Agent 曾问客户是否已经在养兰，客户没有回答，转而说“你们直播间说有资料的，我要资料”。
- 当前客户消息：索要直播间提到的养兰资料。
- 可用工具和真实数据：`material.search` 可找到“萧岚苑陪伴养兰资料”，`material.send` 可准备真实卡片。
- 期望 Agent 理解：客户索要说明有学习兴趣，但养兰经验和需求都未知，资料尚未形成匹配；应先换一个低压力角度继续挖需，本轮不发送。
- 可以接受的行动：先说明资料能覆盖哪些方向以及回答后的客户收益，然后只问一个关于养兰经验、当前问题或选择偏好的容易问题。
- 明显不好的行动：把资料当公开附件立即发送；用“必须回答才能领取”暴露门槛；原封不动重复前一个问题；一次追问多个信息点；发完被动结束。
- 是否允许发送资料或商品卡片：本轮都不允许。
- 参考回复（不是唯一答案）：“有的，里面有新手入门和常见养护。我先帮您找最用得上的部分，您是准备从第一盆开始，还是家里已经养着兰花了？”
- 评分理由：测试资料索要不会覆盖前期信息收集，同时保持自然、低压力和单信息点。

- 案例 ID：`material_earned_003`
- 客户背景：客户已说明从未养过，想选第一盆好养的兰花，家里是南向通风阳台。
- 历史上下文：Agent 已逐轮确认经验、目标和主要环境，当前事实足以形成新手选品理由。
- 当前客户消息：“你结合我的情况给我看看吧。”
- 可用工具和真实数据：`material.search` 可找到新手资料；`product.search` 可返回当前在售、适合新手和该环境的真实商品；对应发送工具均可用。
- 期望 Agent 理解：资料已经通过交流获得明确匹配理由；此时不应继续无效盘问，应释放资料并主动给出少量产品建议。
- 可以接受的行动：搜索并发送匹配资料，说明阅读重点；查询并推荐一款或少量真实商品，结合客户事实解释适配，给出自然下一步。
- 明显不好的行动：仍只问问题不推荐；发资料后让客户自己看；堆砌多个无匹配理由的商品；编造价格或库存。
- 是否允许发送资料或商品卡片：两者都允许，前提是引用真实且队列可发送。
- 参考回复（不是唯一答案）：“按您第一次养、阳台通风这个情况，这份新手资料先看上盆和浇水判断最实用。” + 资料卡片 + “第一盆我更建议从好适应的新手建兰开始，养护压力小一些，这款和您家里的条件更合适。” + 商品卡片。
- 评分理由：测试完整主线是否形成“逐轮收集信息—判断充分—释放资产—主动推品”，而不是等待客户再次发出购买口令。

## 工具选择黄金样本

每个工具至少准备：

- 5 个直接需要调用的表达。
- 5 个间接表达但应该调用的表达。
- 5 个看似相关但不应该调用的反例。
- 3 个与相似工具容易混淆的案例。
- 3 个工具失败或信息不足的案例。

## 直接替换与持续验收

开发期不进行影子运行、真实客户灰度或新旧双轨。主决策入口已经一次性替换；以下条目继续作为正式部署前和后续迭代的质量门槛：

- 严重错误允许数量：完整离线验收样本中为 0；任何跨客户泄露、虚构交易事实或绕过队列均阻止替换。
- 相比当前系统，以下指标必须提升：非标准表达召回、工具选择准确率、资料时机、成熟成交机会处理、回复自然度、无效追问率和未成熟客户的过早推品率。工具调用精确率与召回率分别至少达到 90%，高风险事实工具召回必须 100%。
- 至少不能下降的指标：微信送达稳定性、订单与商品事实准确性、人工接管、技术不可发送状态执行、严重错误率、客户信息隔离和平均响应成功率。
- 现有评测门槛：完整跑完当前 55 条 dataset v2；严重错误为 0；综合得分至少比当前可比较基线 34.68 提升 15 分，并达到 70 分。
- 每日触达专项门槛：可发送客户日完成率 100%；普通客户超过两次、明确拒绝客户超过一次、不可发送客户绕过发送、当天已有回复仍重复补发的数量均为 0。
- 人物风格门槛：小兰风格案例覆盖初次咨询、养护、选品、成熟成交、拒绝后次日触达、已购服务和人工接管；不得依赖固定文本相似度评分。
- 替换方式：主决策入口已一次性切换；旧意图、阶段和固定路由不继续运行。
- 什么情况立即回滚：任一严重错误；微信重复发送或队列绕过；每日触达明显漏发或超频；人工接管失效；事实幻觉上升；工具错误调用影响其他客户；发送失败被当作成功。
- 回滚方式：使用替换前 Git 基线和清晰提交执行 `git revert`，重新部署主分支；不依赖运行时旧架构开关，不使用破坏性强推。
- 最终批准：产品、业务 / 销售和技术负责人在离线报告与回滚演练完成后共同确认直接替换。

## 评测反馈如何转化

出现坏案例时，按以下顺序排查：

1. 客户上下文是否缺失或错误。
2. 工具描述是否让模型找不到或混淆能力。
3. 工具返回是否缺少做判断所需的事实。
4. 销售核心或经验是否没有解释关键判断。
5. 模型能力或上下文预算是否不足。
6. 只有涉及真正硬边界时才增加执行规则。

不要默认用新的关键词、阶段或固定回复修补每个失败案例。

上线后的真实会话只用于正常运行监控和后续经验改进，不建立一套同时运行的旧架构回复作为影子对照。
