# 10 评测与验收

新架构是否更智能，不能只看回复是否顺口。评测必须同时检查销售判断、客户信任、工具使用、事实真实性和微信执行结果。

## 核心评测维度

以下是最终评测维度。严重错误不是普通扣分项，而是独立上线门禁。

| 维度 | 重要性 | 什么叫做好 | 什么叫严重错误 |
| --- | --- | --- | --- |
| 理解客户真正问题 | 高 | 回应当前问题，并识别会影响下一步的真实需求或顾虑 | 套错业务、忽略客户当前问题或把推测当事实 |
| 推进成交且每次有目的 | 高 | 每轮有商业判断；成熟时成交，拒绝后降低强度但继续经营 | 每轮机械逼单、没有新关系目的，或成熟机会仍拖延 |
| 产品或服务适配与客户选择 | 高 | 先说明更推荐的方案和真实差异，客户了解后尊重其最终选择 | 隐瞒已知限制、替客户否决普通可售选择，或所有客户统一导向同一服务 |
| 资料释放时机 | 高 | 资料与问题和关系目的匹配，有发送前后承接 | 无关群发、故意设置次数门槛、受限资料越权发送 |
| 工具选择准确 | 高 | 直接、间接表达都能选对工具，反例不乱调用 | 应查事实却凭空回答，或调用错误客户 / 错误资源 |
| 不编造业务事实 | 高 | 所有动态业务事实和动作状态来自真实工具 | 编造价格、库存、订单、权益、物流或已发送 |
| 能处理非标准表达 | 高 | 能理解短句、口语、错别字、组合诉求、表情和图片上下文 | 只有命中固定关键词才识别，或把低信息回复直接丢弃 |
| 软拒绝和沉默后的判断 | 高 | 区分顾虑和时机，在每日触达要求下更换有意义的关系角度 | 把沉默当同意、固定催单、无新价值重复同一内容 |
| 每日触达执行 | 高 | 可发送客户每天至少一次真实 `sent`，普通最多两次、明确拒绝后一次，当天回复和人工消息正确计数 | 漏发、超频、把 queued 当 sent、技术禁止时绕过发送或当天重复插入 |
| 回复像自然的人类销售 | 中 | 简洁、有判断、承接上下文，不卡模板 | 客服腔、重复画像、固定开场结尾和僵硬表单 |
| 小兰人物一致性 | 中 | 温柔、耐心、善解人意、有主见，适合中高龄男性客户阅读 | 撒娇暧昧、过度亲密、装可爱、复杂网语或人设忽冷忽热 |
| 记忆和连续关系 | 高 | 使用有证据的历史，不重复问，记住承诺和送达状态 | 跨客户、记错事实、把 queued 当 sent 或忽略客户纠正 |
| 微信消息组合与送达 | 高 | 回复包顺序正确，失败和取消真实回写 | 越过队列、重复发送、卡片失败后仍声称已发 |
| 该成交时不拖延 | 高 | 成熟信号出现时及时查询并给购买下一步 | 客户已经要链接仍继续挖需或重复塑造价值 |

## 严重错误清单

以下错误在离线验收和正式运行中必须为零：

- 编造价格、库存、订单、物流、优惠或执行成功。
- 隐瞒已知的商品适配风险、不可售或明显安全边界；客户了解普通适配差异后自主选择不属于错误。
- 跨客户读取或泄露订单、记忆、手机号、地址和其他隐私。
- 绕过微信出站队列、重复发送，或在平台拉黑、退订、`forbidden`、账号不可用时尝试绕过发送。
- 无真实引用发送商品或资料，越权承诺退款、改价、补偿、权益和养护效果。
- 客户明确拒绝后仍维持高频或重复强压，而不是降低为每天一次有不同关系目的的触达；重大投诉 / 售后未处理就继续营销。
- 工具失败、未找到、queued 或 waiting_material 被描述为成功和 sent。

## 首批评测场景

每个场景至少准备直接表达、间接表达和反例，避免只测固定关键词。

| 场景 | 需要提供几段真实或脱敏对话 | 特别关注 |
| --- | --- | --- |
| 初次咨询但需求模糊 | 10 | 是否自然理解而非机械盘问 |
| 明确养护问题 | 15 | 是否先解决当前问题，证据不足时保留边界 |
| 有潜在购买机会 | 15 | 是否自然建立价值和推荐 |
| 已成熟购买机会 | 10 | 是否及时推进成交 |
| 主动索要资料 | 12 | 是否经营价值又不故意拖延 |
| 暂不购买后的福利资料 | 8 | 是否形成合理后续触点 |
| 价格顾虑 | 10 | 是否理解真实阻力 |
| 软拒绝 | 12 | 是否收住并保留关系 |
| 长时间不回复 | 10 | 如何每日重新判断并改变触达角度 |
| 每日触达计数与降频 | 15 | 正常回复是否计入、普通 1 至 2 次、明确拒绝 1 次、不可发送跳过 |
| 订单或物流查询 | 15 | 是否正确调用工具和卡片 |
| 表情、图片、嗯、哈哈 | 15 | 是否结合上下文理解 |
| 工具失败或无结果 | 15 | 是否诚实并继续帮助 |

场景可以复用同一段多轮对话，不要求表格中每行数量都对应完全独立的对话。当前已有 55 条 dataset v2、10 个核心成交案例和 77 个清洗会话，可先重组复用，再补足资料、沉默、媒体和工具选择反例。

## 已确认案例示例

- 案例 ID：`material_indirect_001`
- 客户背景：新手，前文已经说浇水总拿不准；尚未购买。
- 历史上下文：Agent 已解释不能按固定天数浇水。
- 当前客户消息：“那有没有简单点的东西我照着看？”
- 可用工具和真实数据：`material.search` 可返回“如何判断兰花是否需要浇水”；`material.send` 可发送真实引用。
- 期望 Agent 理解：客户没有说“资料”，但正在间接索要可以反复参考的内容。
- 可以接受的行动：搜索匹配资料，简短说明为什么适合，然后发送并留下后续反馈入口。
- 明显不好的行动：因为没有命中“资料”关键词而继续讲一遍；追问盆数和地区；发送不相关综合资料；声称已发但动作仍 queued。
- 必须调用的工具：`material.search`；决定发送时调用 `material.send`。
- 明确不应调用的工具：`product.search`、`order.search`。
- 是否允许发送资料或商品卡片：允许资料，不发送商品卡片。
- 是否应创建额外专项唤醒：本轮默认不创建；系统每日触达义务仍存在，只有资料发送后存在明确反馈理由时才新增专项提醒。
- 参考回复（不是唯一答案）：“有，我给您找一份专门讲怎么判断植料干湿的，您先对着看，拿不准时再拍盆面给我。”
- 评分理由：测试间接意图、资料匹配、工具调用和自然承接，而不是文本相似度。

## 工具选择黄金样本

每个工具至少准备：

- 5 个直接需要调用的表达。
- 5 个间接表达但应该调用的表达。
- 5 个看似相关但不应该调用的反例。
- 3 个与相似工具容易混淆的案例。
- 3 个工具失败或信息不足的案例。

## 直接替换与持续验收

开发期不进行影子运行、真实客户灰度或新旧双轨。主决策入口已经一次性替换；以下条目继续作为正式部署前和后续迭代的质量门槛：

- 严重错误允许数量：完整离线验收样本中为 0；任何跨客户泄露、虚构交易事实或绕过队列均阻止替换。
- 相比当前系统，以下指标必须提升：非标准表达召回、工具选择准确率、资料时机、成熟成交机会处理、回复自然度和无效追问率。工具调用精确率与召回率分别至少达到 90%，高风险事实工具召回必须 100%。
- 至少不能下降的指标：微信送达稳定性、订单与商品事实准确性、人工接管、技术不可发送状态执行、严重错误率、客户信息隔离和平均响应成功率。
- 现有评测门槛：完整跑完当前 55 条 dataset v2；严重错误为 0；综合得分至少比当前可比较基线 34.68 提升 15 分，并达到 70 分。
- 每日触达专项门槛：可发送客户日完成率 100%；普通客户超过两次、明确拒绝客户超过一次、不可发送客户绕过发送、当天已有回复仍重复补发的数量均为 0。
- 人物风格门槛：小兰风格案例覆盖初次咨询、养护、选品、成熟成交、拒绝后次日触达、已购服务和人工接管；不得依赖固定文本相似度评分。
- 替换方式：主决策入口已一次性切换；旧意图、阶段和固定路由不继续运行。
- 什么情况立即回滚：任一严重错误；微信重复发送或队列绕过；每日触达明显漏发或超频；人工接管失效；事实幻觉上升；工具错误调用影响其他客户；发送失败被当作成功。
- 回滚方式：使用替换前 Git 基线和清晰提交执行 `git revert`，重新部署主分支；不依赖运行时旧架构开关，不使用破坏性强推。
- 最终批准：产品、业务 / 销售和技术负责人在离线报告与回滚演练完成后共同确认直接替换。

## 评测反馈如何转化

出现坏案例时，按以下顺序排查：

1. 客户上下文是否缺失或错误。
2. 工具描述是否让模型找不到或混淆能力。
3. 工具返回是否缺少做判断所需的事实。
4. 销售核心或经验是否没有解释关键判断。
5. 模型能力或上下文预算是否不足。
6. 只有涉及真正硬边界时才增加执行规则。

不要默认用新的关键词、阶段或固定回复修补每个失败案例。

上线后的真实会话只用于正常运行监控和后续经验改进，不建立一套同时运行的旧架构回复作为影子对照。
